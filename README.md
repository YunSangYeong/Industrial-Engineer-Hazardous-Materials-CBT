# Industrial-Engineer-Hazardous-Materials-CBT
위험물산업기사

## 개발 상태

React + TypeScript + Vite 정적 학습 앱입니다. 전기기능사 기준 앱의 실제 코드를 재사용했고 위험물산업기사 전용 저장 키·과목·시간·과락 판정을 분리했습니다. 서버·로그인·유료 API·비밀키는 필요하지 않습니다.

**문제은행: 내부 검토 후 등록 1,000문항 / 목표 1,000문항, 부족 0개.** 공식 규칙 원문 확인과 외부 전문가 검수는 미완료이며, GitHub API 사전 확인 403 이후 배포는 중단 상태입니다. 공식 시험 재현·전문가 검수 완료·배포 성공을 주장하지 않습니다.

- 최신 표준 v1.4.0: `YunSangYeong/electrician-cbt` main 커밋 `76b990b8720adfa85c22a0a8f699b17094aa357b`에서 스킬 폴더 전체 복사.
- 앱 코드 기준: `b9a682ccff1b460334b78d5bfad9375b7ec4fbb6`. 소스 MIT 고지를 LICENSE에 보존. 원본 전기 문제은행은 포함하지 않음.
- 기존 AGENTS.md는 없었으며 새 파일에 스킬을 연결함. 스킬 파일 복사는 계정 공통 스킬 설치와 다름.

## 기능

실전 모의시험·랜덤 문제풀이, 과목별 연습, 절대 종료 시각 타이머, 새로고침 복원·만료 자동 제출·중복 제출 방지, 답안 수정, 과목별 채점·과락, 전체 해설·오답만 보기·재학습, 오답노트, 북마크, 통계, JSON/CSV 등록·중복 제거·검증 대기·근거 입력 후 로컬 승인, 검색·페이지·양식·내보내기, 학습 기록 백업·확인 후 초기화를 제공합니다.

두 모드 모두 답안 선택 뒤 Space로 다음 문제에 이동합니다. 랜덤은 즉시 채점, 실전은 시험 중 해설을 숨깁니다. 미응답·반복 키·IME·수정 키·입력 컨트롤·메뉴·대화상자를 보호하며 마지막 실전 문항에서 Space로 자동 제출하지 않습니다. 학습 기준·연도 버전 선택 메뉴와 상단 상시 면책 배너는 없습니다. 규칙·출처·검토 한계는 문제은행 관리와 문서에서 확인합니다.

모바일 메뉴는 독립 세로 스크롤, `100vh`/`100dvh`, 항목 높이 유지, overscroll 차단을 적용했습니다. 작은 화면·가로 모드·확대 글자에서 휠과 실제 CDP 터치 입력으로 하단 백업/초기화와 상단 대시보드 접근을 검사합니다.

## 시험 규칙과 문항

[규칙 확인 기록](docs/exam-rules.md), [문항 검토·이용 조건](docs/question-review.md).

현재 **학습용 가정**: 일반화학 / 화재예방과 소화방법 / 위험물의 성질과 취급 각 20개, 총 60개, 90분, 4지선다. 과목별 100점, 평균 60점 이상 및 각 과목 40점 이상. 미응답은 오답. 공식 Q-Net 페이지의 CONNECT 403 때문에 최신 공식 자료와의 대조는 미완료입니다. 설정은 `src/qualification.ts`에서 관리합니다. 법령 수치·지정수량 문제는 포함하지 않았습니다.

| 과목 | 개념형 | 숫자 조건 변형 | 합계 |
| --- | ---: | ---: | ---: |
| 일반화학 | 60 | 290 (16개 계산 문맥) | 350 |
| 화재예방과 소화방법 | 55 | 270 (15개 계산 문맥) | 325 |
| 위험물의 성질과 취급 | 55 | 270 (15개 계산 문맥) | 325 |
| 전체 | 170 | 830 (46개 계산 문맥) | 1,000 |

기출 0, 복원 0, 자체 제작 1,000. 기존 120개는 ID·내용·정답·해설을 그대로 보존하고 개념형 80개와 계산 40문맥×20조건=800개를 추가했습니다. 기존 계산 6문맥×5조건=30개와 합쳐 숫자 변형은 830개입니다. ID·정규화 본문·보기 재배치 중복 제거 후 내부 검토 상태입니다. 원고의 단일 정답·해설 논리는 동일 AI 작업에서 검토했고 계산 830개는 생성 코드와 별도 산식으로 수치·단위·반올림·동치 보기를 검사했습니다. family 46개는 문맥을 구분한 수이며 비례식 등 핵심 공식이 공유되므로 46개의 독립 수학 개념이나 공식 출제 단원이라고 세지 않습니다. 공식 출제기준 대조와 외부 전문가 검수는 미완료입니다. 숫자 조건 변형을 별도 기출이나 독립 유형으로 부풀리지 않습니다. 연도·회차는 모두 null입니다. 양식은 검증 대기이며 개인 등록분은 공용 수량에서 제외합니다.

## 로컬 개발

Node.js 24.19.0 (`.node-version`), npm lockfile, Python 3 (문항 재생성 검사)를 사용합니다. 실제 검증 환경은 Python 3.12.14입니다.

```sh
cd /workspace/Industrial-Engineer-Hazardous-Materials-CBT
npm ci --cache /tmp/hazmat-npm-cache --no-audit --no-fund
npm run dev -- --port 5173 --strictPort
```

```sh
npm test
npm run build
# 환경 제공 Chromium이 있는 경우
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
# 일반 개발 환경에서 제공 브라우저가 없다면 먼저:
# npx playwright install --with-deps chromium
# npm run test:e2e
```

`npm run test:e2e`는 프로덕션 빌드 후 preview로 PC/모바일 브라우저 기능 검사를 수행합니다. 테스트 결과는 [검증 기록](docs/validation.md)에 분리합니다. 실물 휴대전화 검증과 에뮬레이션을 혼동하지 않습니다. 내부 개발 화면 주소는 공개 배포 주소가 아닙니다.

```sh
python3 scripts/generate_bank.py
```

기본·확장 원고(`scripts/concepts.tsv`, `scripts/concepts-expanded.tsv`)와 계산 문맥(`scripts/expanded_calculations.py`), 고정 시드·ID·정렬로 은행·집계 JSON과 가져오기 양식을 재생성합니다. 실제 유형별 집계는 `src/data/bank-summary.json`에도 저장합니다. 일반 개발에서 문항 생성 없이 `npm ci`와 `npm run dev`만으로 실행할 수 있습니다.

## 저장과 권리

`hazardous-materials-cbt:v1` namespace를 사용해 같은 소유자의 다른 Pages 앱 기록과 분리합니다. 최근 응답 5,000개, 최근 시험 30개, 진행 중 시험·연습·오답·북마크·로컬 등록 문항을 해당 브라우저의 localStorage에 저장합니다. 통계는 보존 중 응답 기준이며 평생 집계가 아닙니다. 저장 실패는 경고하고 손상 원본을 자동 덮어쓰지 않습니다. JSON 백업 내보내기를 제공하며 **백업 UI 복원은 없습니다**. 초기화는 확인 후 개인 데이터만 지우고 기본 은행은 유지합니다. 시크릿·iframe 저장 제한과 origin 차이에 따라 기록이 분리되거나 저장되지 않을 수 있습니다.

자체 작성 문항·양식은 적용 가능한 권리 범위에서 CC BY 4.0, 앱 소스는 MIT입니다. 외부 기출의 재배포 권한을 획득했다고 주장하지 않습니다. 비공식 학습 서비스이며 Q-Net/한국산업인력공단과 무관합니다.

## GitHub 반영과 배포

[배포 기록](docs/deployment.md). 기본 workflow는 main push → 검증 성공 → Pages 자동 배포, PR은 검증만입니다. **이번 작업은 첫 API 사전 확인 403 이후 배포를 중단했습니다.** 배포 없는 기능 브랜치에만 `[skip ci]`로 코드를 보존합니다. main 푸시·수동 실행·워크플로 재실행·대체 배포를 하지 않습니다. 이전 프로젝트도 수정·재배포하지 않았습니다.

예상 기본 주소: https://YunSangYeong.github.io/Industrial-Engineer-Hazardous-Materials-CBT/ (배포 성공과 공개 접근 모두 미확인).

사용자가 지금 확인할 최소 설정: 대상 저장소 Settings → Pages → Source가 GitHub Actions인지 확인·선택. 이미 설정되어 있으면 변경할 필요가 없습니다. 이후 마무리는 사용자가 직접 하며, 에이전트는 새로운 명시적 재시도 요청 전 배포를 다시 시작하지 않습니다.
