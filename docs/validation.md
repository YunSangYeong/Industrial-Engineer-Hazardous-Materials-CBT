Node.js 24.19.0, Python 3.12.14. Chromium은 환경 제공 바이너리를 사용했다. PC는 Desktop Chrome 에뮬레이션, 모바일은 Pixel 7 및 별도 터치 컨텍스트다. **실물 휴대전화, iOS Safari, 다른 실제 브라우저, 블로그 iframe은 미검증**이다.

## 브라우저 검사 범위

- 18개: PC/모바일 두 모드·60문항 답안·북마크·새로고침·합격 결과·전체 해설·오답 복습·90분 만료·재접속 만료·중복 제출·답안 변경 경계·랜덤 즉시 채점·오답 해제·연속 정답·기록·과목 통계·JSON/CSV 등록·중복 제거·검증 대기·로컬 승인·원자적 오류 처리·초기화·Space·네이티브 버튼·컨트롤·대화상자 보호.
- 4개: 저장 실패 경고 유지, 학습 기준 및 상단 criteria 배너 부재, 실전 Space IME·repeat·수정키·열린 메뉴 보호, 실제 keydown/keyup.
- 12개: 390×480/740×360/390×480 글자 200%, 휠과 CDP touchStart/touchMove/touchEnd를 각각 사용. 하단 백업 다운로드·초기화 대화상자 취소·상단 대시보드 복귀와 메뉴 닫기·가로 넘침 부재를 확인. scrollTop은 읽어서 검사하며 프로그램으로 설정하지 않는다. 입력이 메뉴 자체를 움직이고 배경이 스크롤되지 않는지 확인했다.
- 첫 브라우저 실행은 26개 통과/4개 실패였다. 확대 글자에서 메뉴 끝까지 무조건 내린 뒤 백업·초기화가 동시에 보여야 한다고 잘못 가정한 검사 문제였다. 실제 입력으로 각 버튼을 찾아 접근하도록 수정했고 메뉴 검사 12개 통과 후 최종 전체 34개를 통과했다. 실패를 숨기거나 제외하지 않았다.
- 초기 0 기록과 대시보드·문항 화면의 스크린샷을 별도 신규 컨텍스트에서 만들고 육안 검토했다. 실제 사용자의 기록을 복사하지 않았다.

## 채점·데이터 확인 범위

49개 단위 검사에는 평균 35/60 불합격·36/60 합격, 과목 7/20 과락·8/20 과락 아님, 평균이 높아도 과락이면 불합격, 절대 시각 복원, 만료 답안 차단, 제출 중복 방지, 랜덤 순회 중복 방지, 가져오기·손상 복원 등이 포함된다. 계산 30개는 별도 JS 산식으로 정답 수치·단위·동치 보기를 검증했다.

모델이 가정대로 동작한다는 검사는 **그 가정이 공식 최신 시험 규칙임을 입증하지 않는다**. 120개 내부 검토는 외부 전문가 검수·공식 출제기준 전체 대조와 구별한다. 1,000개 목표는 880개 미달이다.

## 원격·배포와 구별

로컬 성공을 CI 성공으로 표시하지 않는다. 첫 GitHub API 사전 확인은 CONNECT 403으로 차단되었고 이후 배포 시도는 없다. Actions 실행·Pages 게시 상태·공개 화면은 미확인이다. 상세 오류와 인계는 [배포 기록](deployment.md)을 따른다.

환경 설정에는 재설치 명령과 프로세스 재시작 지침을 install_script/start_skill 초안으로 저장했다. 이는 현재 인스턴스의 실행 검증과 별개이며 새 작업 복원·설정 게시 성공을 검증한 것은 아니다.
